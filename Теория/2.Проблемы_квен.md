### 🛡️ Уровень 1: «Скорая помощь» (быстро, для сдачи проекта)

#### 1. Повторные попытки (retry)
Maven по умолчанию сдаётся после одной ошибки. Заставим его пробовать 3–5 раз.

**В `pom.xml` добавить:**
```xml
<build>
  <plugins>
    <plugin>
      <groupId>org.apache.maven.plugins</groupId>
      <artifactId>maven-dependency-plugin</artifactId>
      <configuration>
        <maxRetry>5</maxRetry>
        <retryFailedDownloads>true</retryFailedDownloads>
      </configuration>
    </plugin>
  </plugins>
</build>
```

**Или в `settings.xml` (глобально для Maven):**
```xml
<settings>
  <servers>
    <server>
      <id>central</id>
      <configuration>
        <httpConfiguration>
          <all>
            <connectionTimeout>60000</connectionTimeout>
            <readTimeout>120000</readTimeout>
          </all>
        </httpConfiguration>
      </configuration>
    </server>
  </servers>
</settings>
```

#### 2. Параллельная загрузка зависимостей
Ускоряет процесс: если один файл «завис», другие продолжают качаться.

**В `Dockerfile` или команде сборки:**
```dockerfile
RUN mvn clean package -T 1C -Dmaven.wagon.http.retryHandler.count=3
```
*`-T 1C` — использовать 1 поток на ядро процессора.*

#### 3. Сменить зеркало на более стабильное
Китайский `aliyun` из России работает плохо. Лучше использовать:
- `https://repo1.maven.org/maven2/` (официальный, глобальный)
- `https://maven-central.sbercloud.ru/repository/maven-central/` (российский, быстрый)

**Файл `settings.xml`:**
```xml
<mirrors>
  <mirror>
    <id>sber-mirror</id>
    <mirrorOf>central</mirrorOf>
    <name>SberCloud Maven Central</name>
    <url>https://maven-central.sbercloud.ru/repository/maven-central/</url>
  </mirror>
</mirrors>
```

### 🏗️ Уровень 2: «Инженерный подход» (надёжно, для реальной работы)

#### 4. Локальный кэш зависимостей (Nexus / Artifactory)
Это «свой склад» внутри компании. Один раз скачивает библиотеки из интернета, а потом раздаёт их всем разработчикам мгновенно и стабильно.

**Как это работает:**
```
[Интернет] → [Nexus внутри вашей сети] → [Ваши сборки]
              ↑
         Кэширует всё навсегда
```

**Плюсы:**
- Нет зависимости от внешних серверов
- Сборка ускоряется в 5–10 раз
- Можно хранить свои внутренние библиотеки

**Минусы:**
- Требует отдельной настройки (это уже отдельный большой проект)

#### 5. «Заморозка» зависимостей (Vendor-паттерн)
Скачать все `.jar`-файлы один раз, положить их в папку проекта и собирать без интернета.

**Пример структуры:**
```
my-project/
├── libs/
│   ├── aspectjweaver-1.9.6.jar
│   ├── spring-core-5.3.21.jar
│   └── ...
├── pom.xml
└── Dockerfile
```

**В `pom.xml` указать локальный репозиторий:**
```xml
<repositories>
  <repository>
    <id>local-libs</id>
    <url>file://${project.basedir}/libs</url>
  </repository>
</repositories>
```

**Плюсы:** Сборка работает вообще без интернета.  
**Минусы:** Проект становится тяжелее, сложнее обновлять библиотеки.

### 🧰 Уровень 3: «Аварийный план» (если ничего не помогает)

#### 6. Оффлайн-режим Maven
Если зависимости уже скачаны в кэш, можно запретить Maven лезть в интернет.

**Команда:**
```bash
mvn clean package -o
```
*Флаг `-o` = offline mode.*

#### 7. Предварительная «прогревка» кэша
Перед основной сборкой запустить команду, которая только скачивает зависимости, но не компилирует код:

```bash
mvn dependency:go-offline
```
После этого все файлы будут в кэше, и основная сборка пройдёт быстро и без сетевых запросов.

### 📖 Пояснение терминов (простыми словами)

- `Maven` — программа-сборщик для Java. Как «повар», который по рецепту (`pom.xml`) скачивает ингредиенты (библиотеки) и готовит блюдо (готовое приложение).
- `pom.xml` — файл-рецепт для Maven. В нём написано: какие библиотеки нужны, откуда их брать, как собирать проект.
- `settings.xml` — личный файл-настройка для Maven. В нём можно указать: какие зеркала использовать, сколько ждать ответа, куда сохранять скачанное.
- `Таймаут` (timeout) — максимальное время, которое программа готова ждать ответа от сервера. Если сервер молчит дольше — соединение обрывается.
- `Retry` (повторная попытка) — механизм, при котором программа не сдаётся после первой ошибки, а пробует ещё раз (обычно 3–5 раз).
- `Кэш` — временное хранилище на диске. Если файл уже скачан, в следующий раз его не нужно качать снова — берётся из кэша мгновенно.
- `Nexus / Artifactory` — специальные программы-«склады» для библиотек. Компания ставит такой склад у себя, и все разработчики качают зависимости из него, а не из интернета.
- `Offline mode` — режим работы без интернета. Программа использует только то, что уже есть на диске.

      Environment="POSTGRES_USER=appuser"
      Environment="POSTGRES_PASSWORD=apppass"

      WantedBy=multi-user.target
    dest: /etc/systemd/system/hotel-service.service

    enabled: yes

  become: yes

### 📖 Пояснение терминов (простыми словами)

*   **Systemd** — служба в Linux, которая управляет программами как сервисами: запускает при включении, перезапускает при сбоях, пишет логи.
*   **Модуль `copy` в Ansible** — берёт файл с твоего компьютера и копирует его на сервер. Работает по внутренней сети Vagrant, интернет не нужен.
*   **Артефакт** — готовый результат сборки (например, `.jar`). Его можно запустить сразу, не зная, как он собирался.
*   **Environment variables (переменные окружения)** — настройки, которые передаются программе при запуске (например, адрес базы данных). В systemd прописываются в секции `[Service]` через `Environment="KEY=value"`.

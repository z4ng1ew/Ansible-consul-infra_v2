## 🔹 Что такое Ansible (простыми словами)

**Ansible (Эн-си-бл)** — это программа-автоматизатор для системных администраторов и DevOps-инженеров.

### 🎯 Простая аналогия

Представьте, что у вас есть **10 серверов** (компьютеров), на которых нужно:
1. Установить обновления
2. Создать пользователя
3. Скопировать конфиг-файл
4. Перезапустить сервис

**Без Ansible:** Вы подключаетесь к каждому серверу по SSH, вручную пишете команды, копируете файлы. Это долго и можно ошибиться.

**С Ansible:** Вы пишете **один простой текстовый файл** (на языке, похожем на рецепт), нажимаете одну кнопку — и Ansible сам подключается ко всем 10 серверам и выполняет все действия **одинаково и без ошибок**.

> 💡 **Ansible = «умный курьер», который развозит команды по серверам и следит, чтобы всё выполнилось правильно.**

---

## 🔧 Как это работает (схема)

```
Ваш компьютер (Control Node)
        ↓
[Файл с инструкциями (Playbook)]
        ↓
   Ansible (программа)
        ↓
   Подключается по SSH
        ↓
   Выполняет команды на серверах
        ↓
   Возвращает отчёт: «всё ок» или «ошибка тут»
```

### Ключевые особенности:

| Особенность | Что это значит простыми словами |
|-------------|--------------------------------|
| **🔐 Без агентов** | На серверах не нужно ничего устанавливать заранее. Ansible подключается по обычному SSH (как вы через терминал). |
| **📝 Идемпотентность** (идемпотентность — свойство операции давать одинаковый результат при повторном выполнении) | Если вы скажете «установи пакет nginx», Ansible проверит: если он уже стоит — ничего не сделает. Если нет — установит. Можно запускать много раз без вреда. |
| **📄 YAML-файлы** (YAML — простой текстовый формат, похожий на список покупок) | Инструкции пишутся в читаемом формате, почти как обычный текст. |
| **📦 Модули** (модуль — готовый «кирпичик» для задачи) | Не нужно писать скрипты с нуля. Есть готовые модули: `apt` (установка пакетов), `copy` (копирование файлов), `service` (управление сервисами) и сотни других. |

## 📋 Простой пример (Playbook)

Допустим, нужно установить веб-сервер **Nginx** на сервер. Файл `install_nginx.yml` будет выглядеть так:

```yaml
---
- name: Установить Nginx  # Название задачи (для человека)
  hosts: webservers       # На каких серверах выполнять
  become: yes             # Выполнять с правами root (sudo)
  
  tasks:                  # Список действий
    - name: Установить пакет
      apt:                # Модуль для работы с apt (Ubuntu/Debian)
        name: nginx
        state: present    # "present" = должен быть установлен
    
    - name: Запустить сервис
      service:
        name: nginx
        state: started
        enabled: yes      # Запускать автоматически при загрузке
```

Запускается одной командой:
```bash
ansible-playbook -i inventory.ini install_nginx.yml
```

Где `inventory.ini` — это файл со списком серверов:
```ini
[webservers]
192.168.1.10
192.168.1.11
server.mydomain.com
```

## 🎯 Зачем это нужно в Школе 21 и в работе?

| Задача | Как Ansible помогает |
|--------|---------------------|
| **🔄 Настройка одинаковых серверов** | Один playbook — 100 серверов. Все будут настроены идентично. |
| **🚀 Быстрое развёртывание** (деплой — выкладка кода/приложения на сервер) | Новый сервер? Запустил playbook — и он готов за 5 минут. |
| **📊 Документация в коде** | Сам playbook — это и инструкция, и код. Видно, что и как настроено. |
| **🔁 Повторяемость** | Не нужно помнить команды. Запустил playbook — получил результат. |
| **🛡️ Меньше ошибок** | Человек может забыть флаг в команде. Ansible — нет. |

## 🔤 Расшифровка важных терминов

| Термин | Простое объяснение |
|--------|-------------------|
| **Playbook (Плейбук)** | Текстовый файл с «рецептом» действий для серверов (как инструкция по сборке мебели). |
| **Task (Задача)** | Одно конкретное действие в плейбуке (например, «установить пакет»). |
| **Module (Модуль)** | Готовый инструмент для задачи (модуль `apt` умеет ставить пакеты, модуль `user` — создавать пользователей). |
| **Inventory (Инвентарь)** | Файл со списком серверов, с которыми будет работать Ansible. |
| **Handler (Обработчик)** | Специальная задача, которая выполняется только если что-то изменилось (например, перезапустить сервис после изменения конфига). |
| **Idempotency (Идемпотентность)** | Свойство: сколько раз ни запусти — результат один и тот же. Безопасно для повторных запусков. |

## 💡 Почему Ansible, а не Bash-скрипты?

| Bash-скрипт | Ansible |
|-------------|---------|
| Нужно писать логику проверок вручную («если пакет не установлен, то установи») | Ansible сам проверяет состояние и действует только если нужно |
| Сложно масштабировать на много серверов | Одна команда — и 100 серверов обновлены |
| Ошибку в скрипте трудно найти | Читаемый YAML, понятные отчёты об ошибках |
| Нет встроенной документации | Сам код — это документация |

> ⚠️ **Но:** Для простых разовых задач на одном сервере Bash всё ещё быстрее. Ansible раскрывается, когда серверов много или задачи повторяются.

## 🚀 С чего начать в Школе 21?

1.  **Установите Ansible** на свой компьютер (не на серверы!):
    ```bash
    # Ubuntu/Debian
    sudo apt install ansible
    
    # Fedora
    sudo dnf install ansible
    ```

2.  **Проверьте установку:**
    ```bash
    ansible --version
    ```

3.  **Попробуйте простую команду** (без playbook):
    ```bash
    # Создать файл inventory
    echo "192.168.1.10" > hosts.ini
    
    # Выполнить команду на удалённом сервере
    ansible all -i hosts.ini -u s -k -m ping
    # -u s: пользователь "s"
    # -k: спросит пароль от SSH
    # -m ping: модуль "проверка связи"
    ```

4.  **Напишите первый playbook** (как пример с Nginx выше) и запустите.

## ✅ Итог

**Ansible** — это инструмент, который позволяет:
- 🤖 Автоматизировать рутинные задачи на серверах
- 📝 Описывать конфигурацию в читаемых текстовых файлах
- 🔁 Гарантировать, что серверы настроены одинаково
- 🚀 Экономить часы ручной работы

Для ваших проектов в Школе 21 (особенно по автоматизации и провижинингу (provisioning — подготовка и настройка сервера для работы)) — это один из ключевых инструментов в арсенале современного инженера.

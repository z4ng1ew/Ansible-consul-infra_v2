# Какую проблему решили — и как

## Проблема (комплексная)

Плагин `vagrant-libvirt 0.11.2` имеет **три бага**, которые наслоились:

1. **Путает SSH-IP трёх ВМ** — все три считались как `192.168.121.X`. Лечил `qemu-guest-agent` и `config.ssh.insert_key = false`.
2. **Использует устаревший `ifup`/`ifdown`** для Ubuntu 22.04 — там их нет, есть только netplan. Лечил `auto_config: false` (запретил Vagrant'у трогать сеть гостя).
3. **netplan в Ubuntu 22.04 + cloud-init глючит с `match: macaddress`** — записывали правильный YAML, но интерфейс не получал адрес. Тут классическая «у systemd-networkd конфликт между cloud-init и нашим файлом».

## Решение — как сделали

Обошли все три бага так:

1. Vagrantfile поднимает ВМ с двумя сетевыми картами и фиксированными MAC-адресами (`52:54:00:11:11:10/11/12`).
2. Внутри каждой ВМ через `qemu-guest-agent` (без SSH!) **записали systemd-юнит** `fix-privnet.service`. Юнит запускает скрипт `/usr/local/sbin/fix-privnet.sh`, который ищет интерфейс по MAC и вешает на него нужный IP командой `ip addr add`.
3. systemd сам при каждой загрузке запускает этот юнит → IP появляется → ping работает.

Это **независимо от Vagrant и netplan** — простой, понятный, надёжный механизм.

## Как это укладывается в чек-лист

Чек-лист 1.2 запрещает только установку **Docker и других инструментов** через shell. systemd-сервис, который вешает IP — это **настройка сети**, не установка инструмента. Это **разрешено**.

Когда будешь объяснять рецензенту — скажи прямо: «netplan на этой связке Ubuntu cloud-image + vagrant-libvirt 0.11.2 не получалось заставить применить адрес. Поэтому использую самописный systemd-сервис. Установка Docker и других инструментов в Vagrantfile **не выполняется** — она будет в Ansible-плейбуке, как и требует чек-лист».

# Что произошло — два бага наслоились

## Баг 1: `guest_exec` падал из-за переноса строк в JSON

В исходной функции мы передавали shell-скрипт прямо в JSON. А в нашем скрипте есть **переносы строк** (heredoc с `EOF`). JSON-парсер `virsh qemu-agent-command` их не любит — отсюда `failed to parse JSON: invalid string sequence`.

Это **не дошло** до самой ВМ — упало раньше, ещё на хосте. Поэтому ничего внутри ВМ не поменялось.

## Баг 2: `vagrant ssh` молча возвращает пусто

```
vagrant ssh manager -c "ip -br addr"
(пусто)
vagrant ssh manager
(возврат сразу)
```

Это **тот же** старый баг плагина — Vagrant идёт по неправильному IP, попадает не туда, ничего не получает. Команды до ВМ не доходят.

# Решение — обходим оба бага через base64

Передадим скрипт в qemu-ga в base64 — там нет переносов строк, JSON счастлив.

Запусти **функцию-один-раз**, потом 3 команды:

```bash
# === Универсальная функция: записать файл и применить netplan ===
fix_netplan() {
  local domain="$1"
  local mac="$2"
  local ip="$3"

  # Скрипт, который выполнится внутри ВМ
  local script="cat > /etc/netplan/60-private.yaml << 'YAMLEOF'
network:
  version: 2
  renderer: networkd
  ethernets:
    privnet:
      match:
        macaddress: '${mac}'
      set-name: privnet
      dhcp4: false
      addresses: [${ip}/24]
YAMLEOF
chmod 600 /etc/netplan/60-private.yaml
netplan apply 2>&1
sleep 2
ip -br addr"

  # Кодируем скрипт в base64 (одна строка — JSON счастлив)
  local b64
  b64=$(echo -n "$script" | base64 -w0)

  # Запускаем через guest-exec — внутри ВМ декодируем и выполняем
  local pid
  pid=$(sudo virsh qemu-agent-command "$domain" \
    "{\"execute\":\"guest-exec\",\"arguments\":{\"path\":\"/bin/sh\",\"arg\":[\"-c\",\"echo $b64 | base64 -d | sh\"],\"capture-output\":true}}" \
    | python3 -c 'import sys,json; print(json.load(sys.stdin)["return"]["pid"])')

  echo "=== $domain (PID $pid) ==="
  sleep 3   # ждём подольше — netplan apply небыстрый

  # Забираем результат
  sudo virsh qemu-agent-command "$domain" \
    "{\"execute\":\"guest-exec-status\",\"arguments\":{\"pid\":$pid}}" \
    | python3 -c '
import sys, json, base64
r = json.load(sys.stdin)["return"]
if r.get("out-data"): print(base64.b64decode(r["out-data"]).decode())
if r.get("err-data"): print("STDERR:", base64.b64decode(r["err-data"]).decode())
print("exitcode:", r.get("exitcode", "?"))
'
}

# === Применяем для всех 3 ВМ ===
fix_netplan src_manager "52:54:00:11:11:10" "192.168.56.10"
fix_netplan src_node01  "52:54:00:11:11:11" "192.168.56.11"
fix_netplan src_node02  "52:54:00:11:11:12" "192.168.56.12"

# === Проверка ===
sleep 2
echo "=== ping с хоста ==="
ping -c 2 192.168.56.10
ping -c 2 192.168.56.11
ping -c 2 192.168.56.12
```

# Если MAC не совпадает с тем, что мы фиксировали в Vagrantfile

Может быть, что libvirt или Vagrant **проигнорировал** наш `mac:` параметр и сгенерировал свой. Проверим **до** записи netplan:

```bash
# Узнать реальные MAC всех интерфейсов в каждой ВМ
check_macs() {
  local domain="$1"
  local b64
  b64=$(echo -n "ip link show | grep -A1 'BROADCAST' | grep ether" | base64 -w0)
  local pid
  pid=$(sudo virsh qemu-agent-command "$domain" \
    "{\"execute\":\"guest-exec\",\"arguments\":{\"path\":\"/bin/sh\",\"arg\":[\"-c\",\"echo $b64 | base64 -d | sh\"],\"capture-output\":true}}" \
    | python3 -c 'import sys,json; print(json.load(sys.stdin)["return"]["pid"])')
  sleep 1
  echo "=== $domain ==="
  sudo virsh qemu-agent-command "$domain" \
    "{\"execute\":\"guest-exec-status\",\"arguments\":{\"pid\":$pid}}" \
    | python3 -c 'import sys,json,base64; r=json.load(sys.stdin)["return"]; print(base64.b64decode(r["out-data"]).decode()) if r.get("out-data") else None'
}

check_macs src_manager
check_macs src_node01
check_macs src_node02
```

Это покажет MAC-адреса всех интерфейсов в каждой ВМ. Если они **не** `52:54:00:11:11:10/11/12`, а какие-то другие (например, `52:54:00:cc:81:a4`), значит Vagrant не зафиксировал MAC, и нам нужно подставить **реальные** MAC в команду `fix_netplan`.

Из прошлого вывода (`fe80::5054:ff:fe11:1110/64`) у менеджера MAC точно `52:54:00:11:11:10` — то есть для менеджера фиксация **сработала**. Но проверить ноды не помешает.

3. **Если MAC отличаются** — подставить реальные значения в `fix_netplan` и запустить

# Без паники — у тебя есть готовый рабочий рецепт

Хорошая новость: у тебя уже **получалось** заставить ping работать (предыдущая сессия, функция `fix_ip`). У нас есть точный, проверенный путь — нужно его повторить и потом **сделать постоянным**, чтобы не отвалилось при следующем включении.

Сейчас ВМ выключены (после внезапного отключения света). Нужно:

1. Поднять ВМ заново
2. Применить рабочий `fix_ip` (с `ip addr add`, не netplan — netplan почему-то у тебя не вешает адрес, а прямой `ip addr add` работает)
3. Сделать настройку **постоянной** через systemd-сервис, чтобы она применялась при каждой загрузке

# Шаг 1 — поднять ВМ

Они должны быть в состоянии `shut off` после внезапного отключения света. Стартуем напрямую через `virsh`, минуя глючный `vagrant up`:

```bash
sudo virsh start src_manager
sudo virsh start src_node01
sudo virsh start src_node02

# Подождать 60 секунд, чтобы все полностью загрузились
sleep 60

# Проверить — должны быть в состоянии "running"
sudo virsh list --all
```

Если статус всех трёх — `running` (запущен), идём дальше. Если какая-то в `paused` — `sudo virsh resume src_NAME`.

# Шаг 2 — применить рабочий рецепт

У нас есть **доказанно рабочая** функция `fix_ip` (с прямым `ip addr add`). Запускаем её:

```bash
fix_ip() {
  local domain="$1"
  local mac="$2"
  local ip="$3"

  local script="IFACE=\$(ip -o link | grep ${mac} | awk -F: '{print \$2}' | tr -d ' ') && ip addr add ${ip}/24 dev \$IFACE 2>/dev/null; ip link set \$IFACE up && echo IFACE=\$IFACE && ip -br addr show dev \$IFACE"

  local b64
  b64=$(echo -n "$script" | base64 -w0)

  local pid
  pid=$(sudo virsh qemu-agent-command "$domain" \
    "{\"execute\":\"guest-exec\",\"arguments\":{\"path\":\"/bin/sh\",\"arg\":[\"-c\",\"echo $b64 | base64 -d | sh\"],\"capture-output\":true}}" \
    | python3 -c 'import sys,json; print(json.load(sys.stdin)["return"]["pid"])')

  echo "=== $domain (PID $pid) ==="
  sleep 3

  sudo virsh qemu-agent-command "$domain" \
    "{\"execute\":\"guest-exec-status\",\"arguments\":{\"pid\":$pid}}" \
    | python3 -c '
import sys, json, base64
r = json.load(sys.stdin)["return"]
if r.get("out-data"): print(base64.b64decode(r["out-data"]).decode())
if r.get("err-data"): print("STDERR:", base64.b64decode(r["err-data"]).decode())
print("exitcode:", r.get("exitcode", "?"))
'
}

# Применяем
fix_ip src_manager "52:54:00:11:11:10" "192.168.56.10"
fix_ip src_node01  "52:54:00:11:11:11" "192.168.56.11"
fix_ip src_node02  "52:54:00:11:11:12" "192.168.56.12"

# Проверка
sleep 2
ping -c 2 192.168.56.10
ping -c 2 192.168.56.11
ping -c 2 192.168.56.12
```

После этого ping должен работать (как уже работал в прошлой сессии).

# Шаг 3 — сделать настройку постоянной

Сейчас `fix_ip` применяет адрес **в RAM**, и при перезагрузке всё пропадёт. Это и есть твоя главная боль. Нужно записать systemd-сервис, который будет применять настройку **при каждой загрузке** автоматически.

⚠️ Прошлая попытка `make_persistent` завалилась из-за плохого экранирования внутри JSON (там было слишком много слешей, наслаивались и портили вывод). Пишу проще — через файл-скрипт + сервис, который вызывает этот файл:

```bash
make_persistent2() {
  local domain="$1"
  local mac="$2"
  local ip="$3"

  # Скрипт состоит из двух частей:
  # 1) пишем shell-скрипт-настройщик /usr/local/sbin/fix-privnet.sh
  # 2) пишем systemd-юнит, который запускает этот скрипт при загрузке
  # Никаких \\\$ внутри JSON-в-base64 — это была причина прошлого провала.
  local script='cat > /usr/local/sbin/fix-privnet.sh << "BASHEOF"
#!/bin/sh
IFACE=$(ip -o link | grep MAC_PLACEHOLDER | awk -F: "{print \$2}" | tr -d " ")
[ -n "$IFACE" ] && ip addr add IP_PLACEHOLDER/24 dev "$IFACE" 2>/dev/null
[ -n "$IFACE" ] && ip link set "$IFACE" up
BASHEOF
chmod +x /usr/local/sbin/fix-privnet.sh
cat > /etc/systemd/system/fix-privnet.service << "SVCEOF"
[Unit]
Description=Set static IP on private network
After=network.target

[Service]
Type=oneshot
ExecStart=/usr/local/sbin/fix-privnet.sh
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
SVCEOF
systemctl daemon-reload
systemctl enable fix-privnet.service
systemctl start fix-privnet.service
echo "=== service status ==="
systemctl is-active fix-privnet.service
ip -br addr | grep -E "192\.168\.56"'

  # Подставить MAC и IP в шаблон
  script=$(echo "$script" | sed "s|MAC_PLACEHOLDER|${mac}|; s|IP_PLACEHOLDER|${ip}|")

  local b64
  b64=$(echo -n "$script" | base64 -w0)

  local pid
  pid=$(sudo virsh qemu-agent-command "$domain" \
    "{\"execute\":\"guest-exec\",\"arguments\":{\"path\":\"/bin/sh\",\"arg\":[\"-c\",\"echo $b64 | base64 -d | sh\"],\"capture-output\":true}}" \
    | python3 -c 'import sys,json; print(json.load(sys.stdin)["return"]["pid"])')

  echo "=== $domain (PID $pid) ==="
  sleep 3

  sudo virsh qemu-agent-command "$domain" \
    "{\"execute\":\"guest-exec-status\",\"arguments\":{\"pid\":$pid}}" \
    | python3 -c '
import sys, json, base64
r = json.load(sys.stdin)["return"]
if r.get("out-data"): print(base64.b64decode(r["out-data"]).decode())
if r.get("err-data"): print("STDERR:", base64.b64decode(r["err-data"]).decode())
print("exitcode:", r.get("exitcode", "?"))
'
}

# Применяем для всех трёх ВМ
make_persistent2 src_manager "52:54:00:11:11:10" "192.168.56.10"
make_persistent2 src_node01  "52:54:00:11:11:11" "192.168.56.11"
make_persistent2 src_node02  "52:54:00:11:11:12" "192.168.56.12"
```

## Что делает этот скрипт — пояснение

1. **`/usr/local/sbin/fix-privnet.sh`** — обычный shell-скрипт (*Bourne shell* — базовая оболочка Linux), который ищет интерфейс по MAC и вешает на него адрес.
2. **`/etc/systemd/system/fix-privnet.service`** — описание systemd-сервиса (*systemd* — главный «дирижёр» процессов в Linux). 
3. **`Type=oneshot`** — сервис выполняется один раз и завершается, не зависая в памяти.
4. **`RemainAfterExit=yes`** — после успешного выполнения сервис помечается как «активный», иначе systemd считал бы его упавшим.
5. **`After=network.target`** — запустить **после** того, как сетевые интерфейсы появятся в системе.
6. **`WantedBy=multi-user.target`** — сервис стартует при входе в нормальный многопользовательский режим (когда система загружена полностью).
7. **`systemctl enable`** — записывает символическую ссылку, чтобы сервис стартовал при каждой загрузке.
8. **`systemctl start`** — запускает прямо сейчас (чтобы не ждать перезагрузки).

## Почему этот вариант надёжнее предыдущего

Прошлая `make_persistent` падала вот на этой строке:
```
Job for fix-privnet.service failed because the control process exited with error code.
```
Причина: внутри `ExecStart=` мы пытались положить shell-команду с **переменными `$IFACE` и `\$2`**. Слешами `\\\$` это плохо переживало многократное экранирование в JSON → systemd получал кривой синтаксис → падал.

Новый вариант **выносит логику в отдельный файл** `/usr/local/sbin/fix-privnet.sh`. systemd видит чистую команду `ExecStart=/usr/local/sbin/fix-privnet.sh` без всяких переменных и шиппинга. Это и проще, и надёжнее.

sleep 60

# Проверить с хоста — должно работать БЕЗ ручного fix_ip

# Дальше — что делать с Vagrantfile и чек-листом

Чек-лист 1.1 говорит: «*There is a vagrant file for creating manager, node01, node02*» — твой Vagrantfile **уже это делает**. Настройка сети (в виде `ip addr add` через systemd) сейчас сделана **руками внутри ВМ**, а не из Vagrantfile, и это **тоже подходит** под чек-лист, потому что:

- 1.2 запрещает только установку **инструментов** (Docker и других)
- Настройка сети через systemd-сервис — **не установка инструмента**

Но для красоты и повторяемости стоит дописать в Vagrantfile shell-провижнинг, который **сам** записывает этот systemd-сервис. Это сделаем после того, как `vagrant destroy && vagrant up` будет работать с первого раза. Сейчас приоритет — поднять то, что есть.

# План действий — кратко

2. `sudo virsh start src_manager / src_node01 / src_node02` — поднять
3. `sleep 60` + `fix_ip` для всех трёх → проверка ping
4. `make_persistent2` для всех трёх → проверка через `virsh reboot src_manager`
5. После рабочего рестарта — переходим к чек-листу 1.3 (SSH-ключ на менеджере)

## По поводу твоего вопроса «можно ли собрать без Docker, потом перенести?»

**Да, технически можно**, и это правда профессиональный подход — но он создаёт больше работы, не меньше:

| Подход | Шагов | Время |
|---|---|---|
| Через docker build (как сейчас) | 1: `docker build -t ... .` | ~1.5 мин/сервис |
| Без Docker, потом upload | 4: `mvn package` → `docker run --rm -v $PWD:/x openjdk:8-jre cp app.jar /x` → `tar` → `scp` → на ноде `mkdir + java -jar` через systemd | ~3 мин/сервис + ручная настройка systemd |

Главное — **на нодах нет Java**. Чтобы запустить `app.jar` без Docker, тебе пришлось бы `apt install openjdk-8` на каждую ноду, написать systemd-юниты, разрулить сеть между сервисами без overlay-сети Docker. **Это в разы больше работы**, не меньше.

То, что у тебя уже работает (`docker build` → `docker save` → `docker load`) — **и есть** профессиональный подход «build on host, deploy via image». Это именно то, чего требует и задание DO_09: «*построить образы локально на хосте, сохранить через docker save, скопировать на ноду*». Не меняй ничего.

Multi-stage build (когда внутри одного Dockerfile идёт `FROM maven AS builder` потом `FROM jre`, копируя только jar) — это **уже** то, что у тебя в Dockerfile делается. Так что ты уже на правильном пути.

ДА, АБСОЛЮТНО! Более того, это профессиональный подход, который используют в реальной работе. Ты мыслишь в правильном направлении! 🎯
Это называется многоэтапная сборка (multi-stage build) или разделение сборки и запуска.

{
  \"insecure-registries\": [\"192.168.56.1:5000\"]
}
EOF
systemctl restart docker"'
